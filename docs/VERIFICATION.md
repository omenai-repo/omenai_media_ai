### Phase 6: generate-draft in Trigger.dev (2026-10-16)

- **Mocked attempts** (`apps/worker/src/trigger/drafts.test.ts`). These run the real task definition, with the SDK's `task()` reduced to its config and a simulated `ctx`.
  - **Persistence and progress:** the task records its attempt, the run ID and progress ("write" while the model writes, "check" at the end), then releases its lock, with one version.
  - **Retry:** a transient outage is rethrown for the engine to retry (not aborted). The task stays queued and locked, and Operations lists it as "retrying automatically, 1 of 3".
  - **Version safety:**
    - An editor's save during the retry takes version 2, and the retried draft takes version 3. Nothing is overwritten.
    - A replayed attempt writes nothing new.
  - **Giving up:** the third failure aborts, releases the lock and reports the failure, and a new request is accepted.
  - **Permanent errors:** a configuration error, or a malformed payload, aborts on attempt 1.
  - **Fixture path:** used only for a fixtures database outside production. A `PRODUCTION` context always calls the real provider.
- **The real engine:** `trigger dev start` ran with a dedicated env file (the `omenai_fixtures` database and empty Gemini, Anthropic and Tavily keys). The dev environment had no queued or delayed runs beforehand.
  - **Registration:** worker version 20261016.1 built and registered every task, including `generate-draft`.
  - **Editorial article:** recorded with `requestDraft` and triggered with `tasks.trigger`. It finished on attempt 1 (6.9 s): one version, the task succeeded with the run ID recorded, and the lock was released.
  - **Instagram caption (with the fixture outage note):** attempt 1 failed and the engine retried after its backoff. Attempt 2 succeeded (5.7 s): `attempts: 2`, error cleared, one version.
  - **Duplicate triggers:** the same idempotency key returned the same run IDs.
  - **Replay:** `trigger runs replay` of the finished article succeeded and wrote no second version.
  - **Cleanup:** the dev worker was stopped, the env file deleted, and the fixtures database reseeded.

### What these checks don't guarantee

- **Passing proves nothing about truth.** A quote that names the right people and repeats the statement's words can still say something else (a test pins this down). The quote is shown beside each statement for the editor to judge.
- **Lexical and English-centred.** Paraphrases sharing fewer than two words are flagged; names in scripts without capital letters aren't recognised as names.
- **A finite event vocabulary.** An event described in other words counts as not answering a date question (research runs: the cautious side). An event word used as the object of another verb ("agreed to return") reads as that event (a test pins this down).
- **Names aren't typed:** a place can pass for a person in a "who" question about a subject the statement mentions.
- **Disagreement** worded differently is missed; two different measures of one subject can be flagged.
- **Statements the model didn't list aren't checked**, and edited draft versions aren't re-checked.

**Fixed the same day** (`research/terms.ts`, `citations.ts`, `evidence.ts`):

1. **Event words inside names** (M1): an event is read from a sentence without its multi-word names (`withoutNames`: "Art Auction East Africa", "the Grand Reopening Festival"). Single capitalised words, and event words in ordinary words beside a name ("sell", "awarded"), still count.
2. **Numbers in words** (H1): cardinal number words compare with digits (`withDigits`: "three weeks" = "3 weeks"; "one" alone and words inside names, such as "Two Brothers", are left alone). A different number in words is now caught as well. Numbers never stand in for the subject: a quote must share at least one word with its statement besides numbers, units and months; and a fact's quote that names none of the statement's names, and either names others or shares fewer than three such words, must get the statement's subject from the source text just before it (`passageBefore`, 400 characters). Conflicting figures are now compared by what each statement adds, so a shared "3 floors" no longer hides "4,200" against "3,800 square metres".
3. **Dates without a year** (S1, H2): a "when" answer needs a year, or a date relative to its source ("this week"). A month or day alone is enough only when the question already gives the year or asks only for the month or day. Otherwise the answer is partial and research starts through the existing fallback; if research can't find the year, the focused answer says so.

## Remaining limitations (as of 2026-10-18)

**Needs approval** (spends money or touches production):

- **Real model behaviour.**
  - Drafts: voice, length, and how faithfully statements are listed. The bounded Gemini check is prepared.
  - Research: exact quotes and labels only. Chat scope and exact-fact behaviour were checked live on one story (8 cases); one model call now decides scope, so it can still misjudge a question, and only the redirect text is deterministic.
  - Focused follow-ups have run live once (2026-10-18); the evidence-accuracy checks have been re-checked live on two cases only.
  - Draft reasoning level: measured (2026-10-17). Switching LinkedIn posts to low is the product owner's call. A draft through the real worker with the Studio preview, and live chat bursts in a browser, aren't approved yet.
  - Discovery calibration of critical issues.
- **Anthropic:** never called. The adapter's request shape (`beta.messages.create` with `output_config` and the fallback beta) is verified only against intercepted HTTP. See DEPLOYMENT.md, section 3.
- **Trigger.dev:**
  - Chat no longer runs on Trigger.dev (ADR-035). Research and drafts have run on the dev engine; retries there haven't been observed live.
  - `processKeepAlive` is on, but the dev supervisor ends an idle process after a fixed 30 s, so only runs within 30 s of each other reuse one (2026-10-17). Production reuse is unmeasured.
  - A full-size discovery run through the orchestrator hasn't happened.
  - The production schedule at midnight Chicago time hasn't fired.
  - The worker hasn't been deployed to production.
- **Deployment:** Vercel, the production Trigger.dev environment, the app-only Atlas user and Network Access, and Resend delivery.
- **Tavily `includeImages`:** now verified live (13 of 14 pages had an image; no extra credits observed).
- **A full-size discovery run on `gemini-3.8-flash`:** live development ran on Flash-Lite during the overload.

**Known product limits:**

- **Evidence checks are source checks.**
  - A found quote shows where a statement came from, not that it's true or that the passage supports it.
  - The date-and-figure check (`detail_not_in_excerpt`) is a deterministic safeguard: it flags a date or figure missing from the quote, but a quote that contains it can still describe something else. Passing it proves nothing more.
  - The ADR-039 checks (a quote about its statement, disagreement, the check on "sufficient") are lexical and only lower confidence. Their limits are listed in "Evidence accuracy across domains and surfaces".
  - Statements Omenai didn't list aren't checked.
  - Edited versions aren't re-checked.
- **Character counts.**
  - X: a bare domain is shown as a range.
  - Instagram and LinkedIn: counted conservatively, since their rules aren't published.
  - Headlines aren't counted against channel limits; social formats have none.
- **Research relevance** is lexical (ADR-026), and discovery is English-only.
- **Password reset** needs Resend.
- **Status codes:** streamed pages return the 404 view with HTTP 200.
- **Chat speed:** the first generated text depends on the provider (3.3–8.7 s measured on `gemini-3.5-flash-lite`); the 2-second target holds only for the page's own response.
- **Chat durability:** no background retries; a failed reply shows "Ask again". The Anthropic adapter doesn't stream yet (replies would arrive whole).
- **Unanswered questions:** a stopped or failed question stays in the conversation without a reply; only the latest one carries the notice.
- **Progress:**
  - The "longer than usual" notes use development timings.
  - A draft's preview updates about once a second.
  - A chat reply followed from another page shows its steps, but its text only once saved.

**Testing gaps:**

- Safari, Firefox, real devices and screen readers.
- The operating-system reduced-motion setting (only Chrome's emulation was tested).
- Screen-reader announcements of progress steps.
- No real editor has used the studio or read the evidence wording.
